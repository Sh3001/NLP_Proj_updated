## 1. Experimental Setup

### 1.1 Dataset and Regional Stratification (`data/small`)
The experimental evaluation is conducted on a regional subset (`data/small`, 74 MB) constructed by `src/make_splits.py` using whole-state regional coherence across two diverse countries:
- **United States:** Oregon (`US:OR`) and Utah (`US:UT`) — predominantly English, Latin script, structured address formats with ZIP/ZIP+4 codes.
- **India:** Kerala (`India:Kerala`) and Madhya Pradesh (`India:Madhya Pradesh`) — multilingual, featuring Malayalam and Devanagari scripts alongside English transliterations, and descriptive/unstructured address formats.

### 1.2 Candidate Generation & Blocking Ceiling (`03_candidates`)
Every matcher evaluated in this project operates on the **exact same candidate pairs** generated by `03_candidates` via reciprocal-rank fusion (RRF) of character 3-gram sparse cosine similarity and fine-tuned `multilingual-e5-small` bi-encoder dense embeddings ($K_{\text{final}} = 5$).
- **Test Candidate Pairs:** 5 candidates per S2/S3 record.
- **Blocking Recall:** R@5 achieves candidate recall bounded by a theoretical ceiling of **Test Macro $F_{0.5} \approx 0.9250$**. Any entity missed during blocking cannot be recovered by subsequent reranking stages.

### 1.3 Strict Data Leakage Prevention (Part A / Part B Partitioning)
To ensure unbiased stacking and calibration:
- Training pairs are split 85% / 15% into **Part A** and **Part B** using deterministic BLAKE2b hashing of S1 entity IDs (`h01(f'AB{SEED}|{o}')`).
- Matchers (`04`, `05a–c`, `06a–f`) are trained exclusively on **Part A**.
- Fusion models in notebook `07` are fitted exclusively on **Part B** (pairs completely unseen by all expert matchers).
- Decision thresholds are tuned strictly on `val`. The held-out `test` split is scored exactly once per model family with test labels unmasked only inside the final scoring evaluator.

## 2. Fusion Methodology: Comparing Five Approaches

Notebook `07_moe_fusion_and_results` systematically benchmarks five fusion architectures over the calibrated matcher predictions:

### A. Mean of Calibrated Experts
Each expert matcher's raw logit $z_i$ is first calibrated into a calibrated probability via univariate logistic regression fitted on Part B:
$$p_i = \sigma(a_i z_i + b_i)$$
The ensemble decision is the unweighted arithmetic mean across all $N$ active experts:
$$p_{\text{mean}}(x) = \frac{1}{N} \sum_{i=1}^N p_i(x)$$
This establishes the performance of traditional post-calibration voting without input awareness.

### B. Logistic Regression Stacking
A global multivariate logistic regression model trained on Part B logits:
$$p_{\text{LR}}(x) = \sigma\left(\sum_{i=1}^N \beta_i \cdot \frac{z_i - \mu_i}{\sigma_i} + \beta_0\right)$$
Assigns static global importance weights $\beta_i$ to each expert, but cannot adapt to record-specific language or data-quality characteristics.

### C. Constant-Gate MoE (Ablation Baseline)
An architectural ablation of the Mixture-of-Experts network where the gate parameters do not receive input features, learning a static parameter vector $w_0 \in \mathbb{R}^N$:
$$w = \text{softmax}(w_0), \quad p(x) = \sigma\left(\sum_{i=1}^N w_i \cdot (a_i z_i + b_i) + c\right)$$
This isolates the contribution of affine calibration ($a_i, b_i$) from dynamic input conditioning.

### D. Input-Conditional Gated Mixture of Experts (Our Primary Model)
A dynamic gating network that conditions expert routing weights $w(x)$ on 11 input-level features $g(x) \in \mathbb{R}^{13}$:
1. **Script One-Hot (4):** `[latin, devanagari, malayalam, other_indic]`
2. **Source Indicator (1):** `is_S3` (uncurated source flag)
3. **Address Completeness (2):** `addr_empty`, `addr_has_number`
4. **Normalized Sequence Lengths (2):** `len(name)/40`, `len(addr)/80`
5. **Retrieval Signals (4):** `tf_cos`, `de_cos`, `rrf_rank / K`, `n_cand / K`

$$\tilde{g} = \frac{g - \mu_g}{\sigma_g}$$
$$h = \text{ReLU}(W_1 \tilde{g} + b_1), \quad W_1 \in \mathbb{R}^{32 \times 13}$$
$$w(x) = \text{softmax}(W_2 h + b_2), \quad W_2 \in \mathbb{R}^{N \times 32}$$
$$p_{\text{GatedMoE}}(x) = \sigma\left(\sum_{i=1}^N w_i(x) \cdot (a_i z_i + b_i) + c\right)$$

> **CRITICAL DATA-LEAKAGE CONSTRAINT:**
> The gate network **NEVER** receives the country label as an input feature. It routes strictly based on script and data-quality indicators. Country-level distributions are evaluated strictly post-hoc.

### E. LightGBM Stacking
A non-linear tree-based ensemble trained on the concatenated feature vector $[\tilde{Z}, \tilde{G}]$ (expert logits plus gate features) using 400 estimators, learning rate 0.05, and max 31 leaves.

## 4. Gate Weight Analysis (Script-Wise & Post-Hoc Country-Wise)

### 4.1 Learned Routing by Script (Direct Gate Feature)
Inspecting the average gate weights $w(x)$ grouped by the input script reveals natural specialization:
- **Latin Script Entities (US & Indian English):**
  - LightGBM: **0.36**
  - BGE Full Fine-Tune: **0.32**
  - IndicBERTv2: **0.03**
  - *Observation:* When address structure is present, the gate relies heavily on LightGBM's parsed address equality features combined with BGE's dense cross-attention.
- **Devanagari Script Entities (Hindi, MP):**
  - IndicBERTv2: **0.40**
  - BGE Full Fine-Tune: **0.18**
  - BGE MoE Head: **0.13**
  - LightGBM: **0.08**
  - *Observation:* The gate dynamically shifts 40% of its decision mass to IndicBERTv2, which was pretrained on Indic corpora, compensating for tokenization fragmentation in standard XLM-R/BGE vocabularies.
- **Malayalam Script Entities (Kerala):**
  - IndicBERTv2: **0.42**
  - BGE Full Fine-Tune: **0.19**
  - BGE MoE Head: **0.14**
  - LightGBM: **0.06**
  - *Observation:* Complex Dravidian agglutination and phonetic variations (`ṟṟa` $\to$ `tta`) receive highest weighting from IndicBERTv2.

### 4.2 Post-Hoc Routing by Country (Never Visible to Model)
Aggregating the learned gate weights across countries after inference confirms that script-based routing generalizes effectively across geographic borders:
- **United States Entities:** LightGBM (0.38), BGE Full FT (0.34), BGE LoRA (0.13), IndicBERTv2 (0.02).
- **India Entities:** IndicBERTv2 (0.31), BGE Full FT (0.22), BGE MoE Head (0.14), LightGBM (0.12), Siamese BiLSTM (0.11).

## 5. Key Findings & Discussion

1. **Gated MoE Beats All Individual Experts:**
   At **0.8924 Macro $F_{0.5}$**, Gated MoE surpasses the best single model (`mDeBERTa-v3` at 0.8860 and BGE MoE head at 0.8765), demonstrating that dynamically arbitrating between specialized models achieves superior precision.
2. **Ablation Confirms the Value of Input Conditioning:**
   Constant-gate MoE achieves 0.8815, whereas Input-conditional Gated MoE reaches 0.8924 (+1.09 F0.5 points). This proves that conditional routing based on script, address quality, and retrieval confidence provides genuine predictive lift over static weighting.
3. **High Precision on Singletons:**
   Singleton accuracy exceeds 99.0%, ensuring that unlinked distractors are rarely assigned false-positive matches.
4. **Complementary Error Profiles:**
   LightGBM dominates structured address disambiguation (sibling branches), while Transformer cross-encoders dominate fuzzy and phonetically varied business names.

## 6. Limitations to State in Report

1. **Distractor Density:** Our splits maintain a training distractor ratio of ~1.2 unlinked records per S1 entity, whereas the official challenge leaderboard exhibited ~2.3 distractors per S1 entity. Test F0.5 values are therefore optimistic compared to competitive competition leaderboards.
2. **Blocking Ceiling:** With $K=5$, true matches missed during candidate generation set an empirical ceiling of ~0.9250 F0.5.
3. **Execution Runtime:** All fusion training and inference execute in under **4.5 minutes on CPU**, fitting well within the 10-minute budget.
